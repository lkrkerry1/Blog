# 博客写作与审查规范

本文件把「洛谷题解规范」在本站的落地方式，以及作者本人明确做过的取舍，整理成一套可执行的审查清单。

**规范优先级：作者本人的约定 > 洛谷题解规范原文 > 本文件的默认值。**
遇到冲突先按「§5 作者覆盖项」处理，再考虑规范原文。

规范原文提取件（若仍存在）：`.tmp/solution-standard.txt`（从作者下载的 HTML 提取，6536 字）。

## 1. 文章结构

### 1.1 整场比赛题解（一篇装多题）

```markdown
（开场段 1~3 句：比赛性质、题量、赛时成绩、整体难度、本文覆盖范围）

## [题号 - 题名](原题链接)

**题意：** 2~3 句交代。

思路正文……

```cpp
// 代码
```

## 下一题……
```

- 开场段**不要省**：`remark-excerpt` 取正文第一个 `paragraph`，没有开场段时卡片摘要会取到第一题的题意。
- 每题一个 `##`，标题里带**题号 + 题名 +（原题号）**，便于目录跳转和外部锚点引用。
- 每题以 `**题意：**` 开头。
- **过于简单的题直接删掉，不写**（见 §5）。

### 1.2 单题题解（散题，一题一篇）

```markdown
> 来源：[洛谷 P2024](https://www.luogu.com.cn/problem/P2024) · 难度：提高+ · 考点：带权并查集

**题意：** 2~3 句。

## 思路

## 代码
```

- 信息行用**引用块**：`blockquote` 节点不参与自动摘要，安全；摘要会正好落在 `**题意：**` 段落上。
- 短题两个 `h2` 足够，不要为了「看起来完整」硬凑小节。
- 长题可加 `## 关键观察` / `## 正确性` / `## 复杂度` / `## 坑点`。

### 1.3 专题连载

正文 + `series` + `seriesOrder`，详见 §3.4。

## 2. Frontmatter 约定

```yaml
---
title: 洛谷 P2024 食物链          # 必填
published: 2026-10-19            # 必填
description: 模板题：维护元素到根的模 3 关系……   # 必写，见 §2.3
category: 题解                    # 题解 | 笔记 | 随笔
tags: [并查集, 洛谷]              # 2~3 个，见 §3
lang: zh_CN
draft: false
series: dsu-topic                 # 可选
seriesOrder: 3                    # 可选
---
```

### 2.1 `title`

| 文章类型 | 格式 | 示例 |
| --- | --- | --- |
| 整场题解 | 赛事 + 轮次 | `LGR-307 SCP2026 第二轮模拟` |
| 散题 | 平台 + 题号 + 题名 | `洛谷 P2024 食物链` |
| 专题笔记 | 专题 + 序号 + 小节 | `并查集（三）：带权与可撤销` |

题解标题必须带**题号**；散题最好带**平台**（同一题在多个 OJ 有不同编号）。

### 2.2 `slug`（= 目录名 `shirones/content/posts/<slug>/index.md`）

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 洛谷 | `lg-` | `lg-p2024` |
| Codeforces | `cf-` | `cf-1234e` |
| AtCoder | `at-` | `at-abc-479` |
| 比赛 | 赛事名 | `lgr-307`、`buaa-national-day-2026` |

- 全 ASCII 小写 kebab-case。
- **发布后不改**（改了就是改 URL）；必须改用目录重命名 `git mv`，并考虑 frontmatter `alias`。

### 2.3 `description` —— 必写

格式：**直接写概述**（考点列表），50~120 字。

- **不加「N 题题解：」这类前缀** —— 题量、文章类型都不是摘要该占的字。
- **不要重复 title 里的赛事名**（title 已经有了，浪费卡片首行）。
- 赛事贴列 2~4 个代表考点；散题写「问什么 + 关键技巧」。
- 不要把正文挪进来。

示例：

```yaml
# 整场题解
description: LNDS 贪心、格雷码分治、可持久化数据结构、数位 DP，含卡快排与 4MB 内存分块。
# 散题
description: 模板题：维护元素到根的模 3 关系，逐条判定说法真假，$O(K\alpha(N))$。
```

回退规则（决定了为什么必须写）：

| 位置 | 没有 description 时 |
| --- | --- |
| 列表卡片 | 用正文**第一个 paragraph**（可能取到第一题题意，而非全篇介绍） |
| 文章页 meta / og / JSON-LD | **退化成 title**（不读正文） |
| RSS description | 空 |

### 2.4 一致性检查

description 里**不要写题数**，所以增删题目时不需要同步数字；但新增/删除考点后要回头看一眼概述是否还准确。

## 3. 分类 / 标签 / 系列

### 3.1 category（每篇 1 个，最多三个大桶）

```yaml
category: 题解    # 整场题解、散题、单题精讲
category: 笔记    # 算法专题、知识点总结
category: 随笔    # 生活、折腾、工具
```

分类是文件夹，**不再细分**。

### 3.2 tags（每篇 2~3 个，四层结构）

| 层 | 词表 |
| --- | --- |
| 平台 | `Codeforces` `AtCoder` `洛谷` |
| 赛事系列 | `ABC` `ARC` `AGC` `xCPC` `buaa` |
| 难度级别 | `Div. 1+2` `Div. 2` `Div. 3` |
| 性质 | `模拟赛` `正赛` |
| 知识点 | `并查集` `树状数组` `线段树` `DP` `数论` `构造` … |

铁律：

1. **写法唯一**（`并查集` 不写成 `DSU` / `Union-Find`；`AtCoder` 不是 `Atcoder`）。
2. **不把 category 当标签**（不要打 `题解` 标签）。
3. **整场题解不穷举算法标签**，以来源为主，最多补 1 个代表考点。
4. 一个标签攒到 2~3 篇才值得独立存在，总量控制。

### 3.3 系列（只在有真实顺序时建）

三种场景：赛事连载（轮次）、专题递进（模板→带权→可撤销）、训练计划。

```yaml
# shirones/content/series/<slug>.md
title: SCP2026 模拟赛题解
status: ongoing        # ongoing | completed
defaultCategory: 题解
```

`slug` 英文 kebab-case，`title` 中文。**散题不进系列。**

## 4. 正文规范（洛谷题解规范落地）

### 4.1 标点与空格

- 全角中文标点，**句末要有句号**。
- 中文与英文、数字、公式之间用**半角空格**：`做 dfs`、`拓扑 dp`、`ABC G 题`。
- 中文标点与英文/数字/公式之间**不加空格**：`$4x-len$。` 而不是 `$4x-len$ 。`。

### 4.2 数学公式

- 数学表达式（运算、常数、变量字母）用 LaTeX；**英文单词、题名、算法名、人名不用 LaTeX**。
- 函数名用正体：`\gcd \max \min \log \det`；未定义函数用 `\operatorname{lcm}`。
- 位运算用 `\operatorname{and}` / `\operatorname{or}` / `\operatorname{xor}`。
- 取模用 `a \bmod b` 或 `a \equiv c \pmod p`；整除用 `\lfloor \frac{a}{b} \rfloor`，不要用 `a/b`。
- 上下标 `a_{b}^{c}`；大数字科学计数法 `5 \times 10^9`。
- **大 O 记号不带常数**，值域/字符集用字母（`O((n+q)\log V)`）。指数里的 2 不算常数，`O(2^n \cdot n)` 可接受。
- 矩阵用 `bmatrix`，连等式用 `aligned`，分段用 `cases`；省略号用 `\dots` / `\cdots` / `\vdots` / `\ddots`。

### 4.3 代码

- 代码块**必须标语言**（```` ```cpp ````）。答案表格之类的非代码内容用 ```` ```text ````。
- 过长代码：本站主题会自动折叠 **≥20 行**的代码块（折叠成 10 行预览），**不要手动拆分**。
- 解法必须写在正文，不能只在代码注释里。
- 不加防抄袭内容。

### 4.4 内容

- 只写与题目相关内容；不整段复制题面（提炼 3 句 + 原题链接）。
- 题目分析必须包含主要思路（用了什么算法/数据结构 + 具体分析）。
- 正文**不写 `#` 一级标题**（会和 frontmatter title 重复）。
- 正文第一段不要以代码块/列表开头（自动摘要会取空）。

## 5. 作者覆盖项（**必须遵守，不要套用规范原文**）

作者已明确以下取舍，审查时**不要**按规范原文来纠正：

| 项 | 结论 |
| --- | --- |
| GenAI 披露 | **不需要标注**。个人站，AI 润色、排版、措辞调整都不必在文末披露 |
| 吐槽 / 加戏 / 赛况感受 | **允许保留**。开场段的「喜提蓝名」这类内容符合个人 blog 定位 |
| 每道题是否写复杂度 | **不强求**。作者没写的不要替他补 |
| 无代码的题 | **不用补**。实现过于简单的题不放代码 |
| 过于简单的题 | **直接删掉该题小节**，不要硬写题解 |
| 补写解法/复杂度 | **禁止**。只能做格式、标点、记号层面的修正 |

> 教训：本工作区曾由 AI 补写 31 处复杂度分析，最终按作者要求全部删除，只保留作者原文的 13 处。

## 6. 审查工作流

1. **先读**：目标文章的 frontmatter + 正文（跳过代码块的分析文字足够判断）。
2. **结构检查**：开场段有无、每题 `**题意：**` 有无、过简题是否该删、description 题数是否匹配。
3. **格式检查**：中英文空格、句末句号、函数名正体、`\operatorname`、代码块语言。
4. **不要越界**：不补解法、不补复杂度、不改技术判断、不删作者感受。
5. **验证**（沙箱内必须带 TEMP 前缀）：

   ```powershell
   $env:TEMP = "$PWD\.tmp"; $env:TMP = "$PWD\.tmp"; npx.cmd astro check   # 必须 0 errors
   $env:TEMP = "$PWD\.tmp"; $env:TMP = "$PWD\.tmp"; npx.cmd astro build
   ```

6. **不要擅自 commit / push**：先给作者看改动摘要，确认后再提交（push 会触发 Cloudflare 构建，见 USAGE.md §7.1）。

### 6.1 批量改文本的坑

用脚本批量改 Markdown 时：

- **必须排除 frontmatter**（`title:` / `category:` / `description:` 等），否则会写入多余标点。曾把 20 个 frontmatter 字段加上句号，需回退。
- 排除代码围栏内的内容（否则会改到代码）。
- 只处理「公式与行内代码之外」的片段做空格插入。
- 改完用 `git diff` 抽查，并跑一次构建。
